# 竞品对比

> 目的：诚实回答「为什么不用现成的 BI / Agent 平台」。对比维度聚焦本项目真正的差异化，而不是罗列功能表。

## 定位一句话

本项目不是「又一个 BI 工具」，而是 **「用自然语言生成大屏、且生成过程本身可被治理」的演示级平台**——差异化不在图表（图表谁都会画），而在**三件事在生成阶段就下沉**：行级权限、成本预算、可观测性。

## 对比表

| 维度 | FineBI / QuickBI / DataWind | Superset / Metabase | 本项目（dba-platform） |
|---|---|---|---|
| 交互范式 | 拖拽 + 写 SQL，**专业分析师** | SQL 编辑器，**工程师** | **自然语言**提问，业务人员直接问 |
| 行级权限 | 数据集级行权限，**配置在元数据层** | 行级安全（Row-Level Security），事后过滤 | ★ **生成阶段 AST 注入**：权限谓词写进 SQL 本身，未注入即拒绝（fail-closed） |
| 成本治理 | 无（或按 seat 计费） | 无 | ★ **预算守卫前置**：LLM 调用前 check-and-reserve，软限降级、硬限熔断 |
| 可观测性 | 自身运行监控（黑盒） | 自身运行监控（黑盒） | ★ **把 Agent 自身当观测对象**：一个 Run 三视角（观测/计量/执行记录） |
| 部署复杂度 | 中（单机/集群） | 中（需 DB + 缓存） | 高（7 外部组件）——**这是劣势，诚实标注** |
| 报表深度 | 强（企业级报表/权限体系） | 强（SQL 生态） | 弱（演示级，面板种类有限） |
| 成熟度 | 商业成熟 | 开源成熟 | **演示级**，非生产 |

## 真正的差异化（三件事，缺一不可）

### 1. 行级权限在「生成阶段」下沉，而非「事后过滤」

传统 BI 的行级权限是**查完再过滤**——敏感数据已经进过内存、日志、甚至 LLM 上下文。

本项目在 SQL 生成的 `sql_guard` 步骤用 **sqlglot AST 注入**行级谓词，且带**合取项兜底断言**：顶层 AND 链上必须存在一个「取值等于权限值域」的谓词、且不在任何 OR 分支内。注入失败 → 拒绝（`SQL_SCOPE_NOT_INJECTED`）。

**硬证据**：`guard` 对抗集 **121/121 全绿**（含 CTE / 子查询 / UNION / `WHERE x='EAST' OR 1=1` / `x IS NOT NULL` 等 25 种注入形态），`permission_boundary` 题 **EX 1.000**。

### 2. 预算在「调用前」检查，而非「账单后」统计

`BudgetGuardAgent` 在 LLM 调用发起前做 check-and-reserve（Redis 快路径 + MySQL 权威账本），软限触发降级/压缩/限流，硬限熔断；**硬熔断默认关闭**（防误配全线熔断）。

### 3. 一个 Run 模型三视角

`trace_id` 贯穿一次提问：ChatBI 看它是执行记录、可观测性看它是观测对象、FinOps 看它是计量对象。**埋点只做一次**，三个模块是同一份运行时数据的三个视角，而不是三套拼起来的系统。

## 为什么自研编排层（不用 LangChain/LangGraph）

| 维度 | 现成框架 | 自研（本项目） |
|---|---|---|
| 埋点注入 | 框架 callback/hook，能力边界受限于框架 | `RunContext` + ContextVar + 装饰器，任意位置可读 |
| 自愈回退 | 用图结构表达「失败带错误回上游重试」，绕 | `Step.on_error='goto'`，二十行 |
| 行级权限 | 框架不关心 SQL 语义 | 直接在 `sql_guard` 步做 AST 注入 |
| 面试价值 | 「我用了 LangGraph」信息量低 | 「我实现了带自愈回退的状态机编排内核」可讲很深 |

> 但**不重复造轮子**：SQL 解析用 sqlglot、重试用 tenacity、Span 用 OpenTelemetry SDK。

## 诚实标注的劣势（不回避）

1. **前端只有对话页 + 观测/FinOps 只读页**：无数据建模界面、无报表管理、无拖拽设计器。
2. **报表/图表深度远不如 BI 商业产品**：面板种类有限（KPI/地图/环形/仪表盘/排行/堆叠柱/面积/拓扑）。
3. **7 个外部组件**，部署门槛高，不适合轻量场景。
4. **评测集 32 题**（设计文档原计划 120 题），覆盖面有限。
5. 真实模型成本曲线依赖**技能复用率**才能体现「自研运行时值得」，而 `skill_usage` 目前无生产写入方（链路未闭合）。
