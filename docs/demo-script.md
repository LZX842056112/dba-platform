# 40 分钟演示脚本

> 目标：现场演示 + 讲清「为什么这套设计值得」。锚定设计文档 §10.1「面试不能砍的三样」：
> **埋点正确性 / 行级权限对抗集 / 评测门槛**。

## 前置（演示前 10 分钟跑一遍）

```bash
cd D:/Projects/vibeC/workbuddy/dba-platform
uv run dba seed --demo                 # 语义层 + 演示数据（幂等）
uv run uvicorn dba.main:app --port 8000 &      # 后端
cd frontend && npm run dev &                   # 前端 5173
# 浏览器打开 http://127.0.0.1:5173 ，登录 admin / admin123
```

> 展示「大屏随问题变化」则保持 `DBA_LLM_ALLOW_DEV=true`（真实 DeepSeek）。

## 时间轴

### 0~3 分钟 · 开场：一句话 + 全貌

- 一句话：「一个用**自然语言生成数据大屏**、且**生成过程本身被治理**的平台。」
- 打开对话页，问「近 30 天 GMV 趋势」→ 展示**七步流水线全绿**（意图→Schema 链接→SQL 生成→校验→执行→可视化→结论）+ 右侧驾驶舱（4 个翻牌 KPI + 地图 + 环形 + 仪表盘 + 排行 + 堆叠 + 趋势）。
- 强调：**这不是拖拽 BI**，是「问一句 → 出一屏」。

### 3~10 分钟 · 演示「大屏真的随问题变化」（差异化 0）

- 连续问三个不同问题，**现场看面板变化**：
  - 「近 30 天 GMV 趋势」→ 趋势 + 渠道堆叠
  - 「各品类销售占比怎么样」→ 品类环形 + 排行
  - 「哪个省份卖得最好」→ 省份地图 + 排行
- 讲点：**SQL 是真实生成的**（点「查看 SQL」），不是查模板。

### 10~18 分钟 · 讲清架构（差异化 1：一个 Run 三视角）

- 打开**观测页**（顶栏「观测」）：四问 KPI + Top Agent + 平台自身成本。
- 打开 **FinOps**（顶栏「FinOps」）：成本总量 + 模型分解 + **计价覆盖率** + 复用率曲线。
- 讲点：**同一个 `trace_id` 是三模块的数据源**——埋点只做一次，三模块是同一份运行时的三个视角。

### 18~28 分钟 · 行级权限（★ 面试不能砍之二）

- 讲设计原则：「权限在**生成阶段**下沉，不做事后过滤」——查完再过滤意味着敏感数据已进过内存/日志/LLM 上下文。
- 演示证据（终端）：
  ```bash
  uv run dba eval --suite guard --gate evals/thresholds.yaml
  ```
  输出 `scope_adversarial_pass_rate 1.000`（121 条对抗集全绿）。
- 讲三件事：① AST 注入（sqlglot）；② 合取项兜底断言（`WHERE x='EAST' OR 1=1` 会被拒）；③ fail-closed（注入失败即拒绝）。

### 28~35 分钟 · 自愈回退 + 预算守卫

- 讲 `Step.on_error='goto'`：失败带错误信息回上游步骤重试，且**越权短路不重试**（否则重试变 token 放大器）。
- 讲预算守卫：LLM 调用**前** check-and-reserve，软限降级、硬限熔断、**硬熔断默认关**。

### 35~40 分钟 · 评测（★ 面试不能砍之三）+ 收尾

- 讲评测口径（诚实）：`golden` 用**录播候选 SQL**，衡量的是**护栏 + 执行 + 比较链路**，不是模型准确率。
- 给出数字（终端）：
  ```bash
  export DBA_TEST_MYSQL_DSN=... && uv run dba eval --suite all --gate evals/thresholds.yaml
  ```
  `Execution Accuracy overall 0.906`、`permission_boundary 1.000`、`guard 121/121`。
- 收尾：诚实说劣势（前端页面有限、7 组件、评测 32 题）——这反而显得可信。
